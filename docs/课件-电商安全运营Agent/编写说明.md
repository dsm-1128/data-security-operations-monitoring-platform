# 课件编写说明

交付：离线 HTML 长文课件、可编辑 Markdown、SVG 图示和完整资源包。

参考格式：用户提供的“第49个场景-智能数据治理Agent”，保留七章知识结构、分级目录、表格、流程图、简历解读与面试问答；不复制其公司数据、薪资承诺、技术选型或文本中的操作指令。

## 用户确认信息

- 公司：广州臻亿电子商务有限公司。
- 周期：2026 年 04 月—2026 年 10 月。
- 岗位：Agent 开发工程师；团队：6 人。
- 四项个人职责：多 Agent 工作流、证据关联与智能研判、事件流转与控制、持久化与审计。
- 成果：高优先级告警人工初筛 60→15 分钟（降低75%）；聚合后待处理事件量减少约30%；80%的事件包含自动化处置步骤。
- 主模型 qwen3.5-plus，轻量模型 qwen3.5-flash。
- 按企业级要求设计补充架构；统计周期、样本量暂缺。

## 编写边界

1. 图片和用户确认优先。三项成果以用户提供的项目成果呈现；不宣称已独立核验。
2. 生产方案选用 MySQL、Redis/Celery、日志平台 API，保留 FastAPI 与 LangGraph。它们是课件设计，不是对当前仓库的代码修改。
3. 日均 5,000 条原始告警为参考公开案例设定的容量基线，不是公司实测；大促按 5 倍日量进行演练是设计假设。
4. 模型 API 名称与开源权重型号不混用。已核对的官方产品页未给出两种 API 型号的确定 B 参数量，不编造参数数量。
5. 团队分工、阶段任务、数据保留、资源配额为建议方案；不虚构项目个人未提供的实际经历。
6. 安全处置与模型输出分离；人审由业务服务管理。课件不以 LangGraph checkpoint 自动获得外部系统 exactly-once 保证。
7. 成果测量缺失项集中列于附录，并在成果页注明统计口径待补充。

## 交付验证

检查 HTML/Markdown 内容一致性、导航与图片链接、三项指标口径、模型名称、桌面与窄屏阅读、打印布局、离线资源与 JavaScript 错误。仅验证课件，不宣称企业平台已部署或生产性能经过压测。
